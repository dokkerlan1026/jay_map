# 台北門市地圖設計規格

## 目標

建立一個簡單、響應式的單頁網站，讓使用者能同時查看店名、地址與地圖位置，並可啟動單店導航或規劃走訪所有示範店家的單向最佳路線。

## 範圍

- 使用 5 筆台北示範店家資料，每筆包含店名、地址、緯度與經度。
- 桌面版採左右雙欄：左側為店家表格，右側為互動地圖。
- 店家表格包含「店名」與「地址」兩欄，另在每筆資料中提供「導航」操作。
- 手機版改為上下排列，先顯示店家清單，再顯示地圖。
- 不建立後端、帳號系統、資料庫或店家管理介面。

## 視覺與互動

- 頁首顯示「台北門市地圖」與簡短使用說明。
- 地圖使用 Leaflet 與 OpenStreetMap 圖磚。
- 點選店家列時，地圖移動到該店並開啟標記資訊。
- 點選地圖標記時，對應的店家列顯示醒目狀態。
- 店家列與主要操作按鈕支援鍵盤操作，並提供清楚的焦點樣式。
- 版面在窄螢幕上保持可讀，避免表格與地圖水平溢出。

## 單店導航

- 每家店提供「導航」按鈕。
- 按下後以 Google Maps 路線網址開啟該店目的地。
- 若網站已取得目前位置，將目前座標帶入為起點；否則交由 Google Maps 讓使用者選擇起點。
- 此功能不需要 Google Maps API 金鑰。

## 全店最佳路線

- 提供「規劃最佳路線」按鈕。
- 優先使用瀏覽器 Geolocation API 取得目前位置。
- 若使用者拒絕定位、定位逾時或瀏覽器不支援定位，使用台北車站作為起點，並在介面中說明。
- 使用 OSRM 公開道路服務取得店家間的行車距離與實際道路路線。
- 路線由起點出發，依建議順序走訪全部 5 家店，最後停在末站，不返回起點。
- 以 5 家店的規模計算全部拜訪順序，依道路距離選出總距離最短的順序；若距離矩陣缺少部分路段，缺失路段改用直線距離估算並顯示提示。
- 地圖以折線呈現完整道路路線，清單同步顯示編號與拜訪順序。

## 元件與資料流

- `stores` 資料陣列是店家清單與地圖標記的單一資料來源。
- 清單元件負責顯示店名、地址、選取狀態與導航操作。
- 地圖元件負責標記、目前位置、路線折線與視野調整。
- 路線規劃器接收起點與店家座標，向 OSRM 取得距離矩陣，計算最佳順序，再要求對應道路幾何並回傳給地圖與清單。
- 目前位置只保存在瀏覽器記憶體中，不上傳到自建服務或儲存到本機。

## 錯誤處理

- OpenStreetMap 圖磚無法載入時，店名、地址與導航按鈕仍可使用。
- OSRM 完全無法回應時，顯示非技術性的錯誤訊息，保留單店導航功能；若只有道路幾何無法取得，則以虛線直線連接建議順序並標示為估算路線。
- 規劃期間停用重複提交並顯示處理狀態。
- 定位失敗時自動使用台北車站，不阻斷路線規劃。

## 技術架構

- 採 buildless 靜態網站：HTML、CSS、原生 JavaScript。
- Leaflet 由 CDN 載入；地圖圖磚來自 OpenStreetMap。
- OSRM 僅用於示範路線規劃，不需要 API 金鑰。介面會妥善處理公開服務的速率限制或暫時失效。
- 網站可直接作為靜態檔案部署，不需要伺服器端執行環境。

## 驗收與測試

- 桌面版顯示左右雙欄，手機版顯示上下排列。
- 5 筆示範店家都同時出現在清單與地圖。
- 清單列與標記可雙向同步選取。
- 每個單店導航連結均指向正確目的地。
- 接受定位與拒絕定位兩種情況都能規劃路線。
- 路線規劃結果包含起點及全部 5 家店，且不返回起點。
- 地圖、定位或路線服務失敗時，頁面顯示適當提示且基本店家資訊仍可讀。
- 主要互動可用鍵盤操作，焦點與狀態文字可辨識。
